# 作品の HTML を書くとき

コードを書く・直す前に、DEVELOPMENT.md の「方針」節を読む。新作や構成の変更なら「ファイルの構成」節（節の順番の表）も読む。仕上げは「作品を追加・変更したとき」節に沿う。見た目を変えないリファクタリングなら「見た目を変えないリファクタリング」節を読む。

要点:

- 1 作品 = HTML 1 ファイル。ビルド・npm は使わない。共通の処理は common.js・common.css に置く。
- スクリプトは `// ---- 設定 ----` などの節に分け、節の順番を揃える。
- 調整できる値は「設定」節に定数で置き、名前で分からない定数には意味・単位・範囲をコメントで書く。
- 時間で進む位相は JS で 0〜2π に収めてからシェーダーに渡す。
- 描く回数を抑えるときは jellyfish.html と同じ `nextDraw` の書き方にする。
- `MAX_PIXEL_RATIO` は `{ pc, touch }` で書く。
- MSAA にするのはシーンを描く描画先だけにする。不透明度を使わない浮動小数点の描画先は `compactHdrFormat` で形式を選ぶ。
- シーンがあれば `SCENES` の各項目に英語の `name` を持たせる。
- 見た目のための乱数を足すときは、既存の `Math.random` を引く回数と順番を変えない（変わると video-compare で比べられなくなる）。
- シーンを替える処理では、`Math.random` で決まる状態（待ち時間・粒など）を作り直すか初期値に戻し、前のシーンから持ち越さない（持ち越すと、video-compare で前のシーンの変更が後のシーンに響く）。隠し要素の専用の乱数で決まる状態は持ち越してよい。
- 簡略化の案には増減する行数を添え、行数が増える案はなるべく避ける。一部の場面だけの特別扱いを足す前に、既存のルール・定数の調整で近似できないかを考える。
