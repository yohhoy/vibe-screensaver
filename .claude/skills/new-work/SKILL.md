# 新作の追加

引数: $ARGUMENTS

- テーマ: 引数か会話から取る。無ければ 1 の案出しで、方向の違う案を並べる。
- 「案のみ」「プランのみ」と言われたら、1 だけ行って止まる（ファイルを作らない）。
- 段階ごとにユーザの返事を待つ。「仕様を作って」と言われたら 2 で止め、「実装に進んで」と言われてから 3 に進む。

## 1. 案を出す

- 既存の作品と重ならないように、`grep -n '^## ' README.md` で作品の一覧を見る。
- 3〜5 案を、1 案 4〜6 行で出す。
  - 作品名（英小文字 1 語。ファイル名になる）と日本語名
  - 何を眺める作品か
  - シーン構成を持つ作品なら、印象の違うシーンを必ず 3 つ出す（時間帯・場所・時代などの軸で、互いに重ならないもの）。シーンが 1 つの作品なら、そう書く
  - 強度で変えるもの
  - カメラ
  - 見どころと、描き方の難しさ・GPU の重さの見込み
- 隠し要素は、ここでは出さない。作品ができてから add-hidden で足す。

## 2. 仕様を書く

- DEVELOPMENT.md の「仕様の書き方」節を読み（`grep -n '^#' DEVELOPMENT.md` で行番号を出す）、`docs/specs/<作品名>.md` を作る。節の順番と表記を揃え、近い既存の仕様（シーンがあれば `docs/specs/bubbles.md`・`orrery.md`）の見出しを手本にする。
- 調整用の定数は並べない。見た目・動きとして意味のある数値と、「なぜそうするか」を書く。
- シーン構成を持つ作品は、ユーザが数を指定しない限り、シーンを 3 つにする。
- 書いたら、シーンごとの印象・強度・カメラを数行にまとめて示し、返事を待つ。

## 3. 実装する

- DEVELOPMENT.md の「方針」と「ファイルの構成」節を読み、`.claude/rules/works.md` の要点に沿う。
- 土台にする作品を 1 つ選ぶ（シーンがある作品なら bubbles.html か orrery.html）。`<head>`・`#hud`・節の順番（`grep -n '^// ----'`）を揃える。
- `tools/pages.mjs` の `PAGES` に作品名を足す。シーン・配色があれば `CHOICES` にも足す。
- 最初の確認として、全シーンを横長と縦長で撮り、1 枚に並べる。

  ```sh
  node tools/video-export.mjs <作品名> --scenes 0,1,2 --warmup 3 --out <scratchpad>/a.png
  node tools/video-export.mjs <作品名> --scenes 0,1,2 --warmup 3 --size 720x1280 --out <scratchpad>/p.png
  node tools/img.mjs grid <scratchpad>/a-*.png <scratchpad>/p-*.png --cols 3 --out <scratchpad>/first.jpg
  ```

  ページのエラーやシェーダーの失敗があると撮影が止まるので、止まらずに撮れることを確かめる。並べた 1 枚を見てから、ユーザに見せる。

## 4. 調整する

ユーザの指摘を受けて直す。1 つの指摘が 1 回の調整になる。

- 調整を始める前に `node tools/video-compare.mjs <作品名> --keep` で控え、比べるときは `--base kept` で、変えたシーンだけを短い `--seconds`（1〜2 秒）で撮る。
- ユーザが見たいと言ったら、並べた画像（`img.mjs grid`）か動画を作って見せる（見せ方は CLAUDE.md の「画像の確かめ方」）。
- 動き・見た目の仕様が変わったら、仕様も同じ回で直す。
- 縦長の画面（`--size 720x1280`）で主役が見切れないか、ときどき確かめる。

## 5. 仕上げる

DEVELOPMENT.md の「作品を追加・変更したとき」節に沿う。ほかの作品の書き方は、`orrery` の行を grep して手本にする。

- [index.html](index.html): 一覧の最後に `<li>` を足す。名前は英語、説明は敬体の 1 文。
- [README.md](README.md): 「開発者向け情報」の前に、作品の節を足す。
  - 見出しは `## [日本語名](https://yohhoy.github.io/vibe-screensaver/<作品名>.html)`
  - サムネイル、2〜3 文の概要、`シーン切替: … / 強度: …` の行
- サムネイル: DEVELOPMENT.md の「作品を追加・変更したとき」節のコマンドで撮る。
- 全シーンを横長・縦長でもう一度撮り、エラーが無いことを確かめる。
- ユーザに tidy-work（リファクタリングと仕様の整合確認）を勧める。
- コミットするときのメッセージは `新作 <作品名>（<日本語名>）を追加する` の形にする。

## 報告

段階ごとに、何を作った・直したか、確かめたこと（撮った場面・大きさ）、次に決めてほしいことを短く書く。
