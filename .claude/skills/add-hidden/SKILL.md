# 隠し要素の追加

引数: $ARGUMENTS

- 作品名: 引数の 1 つ目。無ければ会話から決める。`tools/pages.mjs` の `HIDDEN` に既にあれば、置き換えるのか、足すのかを先に聞く。
- 演出の内容が決まっていれば 1 を省き、2 から始める。
- 段階ごとにユーザの返事を待つ。

## 1. 案を出す

- 作品の仕様の冒頭の概要と見出し（`grep -n '^#' docs/specs/<作品名>.md`）を見て、作品の世界を押さえる。
- 既存の隠し要素と雰囲気を揃えるため、README.md の `<details>` の中身を見る（`grep -A3 '<summary>隠し要素' README.md`）。
- A〜F ほどの案を、1 案 2〜3 行で出す。
  - 何が現れ、どう動いて、どう去るか
  - 長さ（秒）
  - 驚きどころ
  - 実装の重さ
- 隠し要素は現実らしさにとらわれなくてよい。作品の主役を邪魔せず、ふだんの絵に混ざって「おや」と気づく程度にする。

## 2. 仕様を書く

- `docs/specs/<作品名>.md` に `## 隠し要素（名前）` の節を足す。置き場所は「強度」の後、「描き方」の前。表記は DEVELOPMENT.md の「仕様の書き方」に合わせる。
  - 間隔: 「ときどき（A〜B 秒おき、平均 C 秒ほどに 1 回）」
  - 隠しキー: 「**C** キーですぐに呼び出せる（操作ガイドには表示しない）。」
  - 暗転中・シーン切替・強度との関わり、出ている間に C を押したときの扱い
- 間隔は、ほかの作品と比べて決める。比べるときは、次の一覧をユーザに示す。

  ```sh
  grep -A3 '^## 隠し要素' docs/specs/*.md | grep 'おき'
  ```

## 3. 実装する

DEVELOPMENT.md の「作品を追加・変更したとき」節の隠し要素の項に沿う。手本は orrery.html の彗星（`grep -n 'comet\|Comet' orrery.html`）。

直し始める前に `node tools/video-compare.mjs <作品名> --keep` で、変更前の版を控える（4 で、ふだんの絵を比べる相手にする）。


- 出現の処理はトップレベルの `function start○○()` にする。
  - 先頭で `if (○○ || isFading()) return;` とする。出ている間と暗転中は何もしない。
  - 待ち時間が切れたときの出現も、C キーも、この関数を呼ぶ。
- 状態は節の中に置く。
  - `○○`: 出ていれば値、いなければ `null`
  - `○○Wait`: 次に現れるまでの秒数。平均・最小・最大から、指数分布で決める（orrery.html の `cometInterval` と同じ形）
- `tick` で `○○Wait` を減らし、0 以下になったら `start○○()` を呼ぶ。
- `setupControls` の `keys` に `KeyC: start○○` を足す。コメントは「隠し要素の○○（操作ガイドには表示しない）」とする。
- 隠し要素の乱数は `Math.random` と別にする（orrery.html の `cometRandom`・bubbles.html の `heartRandom` と同じ mulberry32）。`○○Wait` の初期値も、この乱数で決める。
  - three.js も物を作るときに `Math.random` を引くので、隠し要素の物（メッシュ・材質など）は、最初に現れたときに作る。
  - `Math.random` を引く回数や順番が変わると、ふだんの絵が変わり、video-compare で比べられなくなる。
- `tools/pages.mjs` の `HIDDEN` に `<作品名>: 'start○○'` を足す。

## 4. 確かめる

- 出た場面: 時刻を変えて撮り（時刻は演出の長さに合わせる）、1 枚に並べて見る。

  ```sh
  node tools/video-export.mjs <作品名> --hidden 0.5 --shots 1,3,5,8 --out <scratchpad>/h.png
  node tools/img.mjs grid <scratchpad>/h-*.png --cols 4 --out <scratchpad>/h.jpg
  ```

  - シーンがある作品は、全シーンで撮る。
  - 縦長の画面（`--size 720x1280`）でも撮る。
- ふだんの絵: `node tools/video-compare.mjs <作品名> --base kept --seconds 2` で比べる。シーンがあれば `--scenes` に全部の番号を付け、「全コマ一致」になることを確かめる。待ち時間は数十秒より長いので、この長さの撮影には出ない。一致しなければ、`Math.random` を引く回数や順番が変わっていないか見る。
- シルエットや形を詰めるときは、背景を明るくして（`--at "0:式"` で背景の色を変えるなど）、`img.mjs grid --crop` で切り出して見せる。

## 5. 仕上げる

- [README.md](README.md): 作品の節の最後に、ほかの作品と同じ形の `<details>` を足す（`<summary>隠し要素（ネタバレ注意）</summary>`）。1〜2 文で書き、最後を「**C** キーですぐに呼び出せます。」で結ぶ。
- サムネイルは撮り直さない。
- 調整の途中で動きが変わったら、仕様も合わせる。
- コミットするときのメッセージは `<作品名> に隠し要素（<短い説明>）を追加する` の形にする。本文は、隠し要素そのものの説明だけにする。

## 報告

段階ごとに、作った・直したこと、確かめたこと（撮った時刻・シーン・大きさ、ふだんの絵が全コマ一致か）、次に決めてほしいことを短く書く。
